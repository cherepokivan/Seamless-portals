# Seamless Portals

**Seamless Portals** — клиентский мод Fabric для **Minecraft Java Edition 26.2**. Его цель — превратить Незер-портал в живое окно в другое измерение. В режиме интеграции с Paper плагином мод показывает внутри проёма реальные блоки небольшой области мира назначения, с перспективой, глубиной, геометрическим параллаксом и временем суток.

> Ванильный клиент обычно загружает чанки только того измерения, где находится игрок. Поэтому для просмотра реальной местности другого измерения до перехода требуется приложенный Paper-плагин. Без него мод сохраняет безопасную локальную анимированную поверхность и не подменяет реальный мир выдуманной картинкой.

## Что реализовано

| Возможность | Fabric-мод | Требуется Paper-плагин |
|---|---:|---:|
| Обнаружение ближайших ванильных Незер-порталов | Да | Нет |
| Двусторонняя пользовательская поверхность с depth-тестом | Да | Нет |
| Скрытие портала препятствиями текущего мира | Да | Нет |
| Сброс кэша после перезахода и смены измерения | Да | Нет |
| Передача реальной геометрии блоков другого измерения | Нет | Да |
| Трёхмерный параллакс при движении камеры | Нет | Да |
| Масштаб координат Верхний мир ↔ Незер | Нет | Да |
| Цвет неба, день/ночь и погода мира назначения | Нет | Да |
| Пиксельно точные ванильные текстуры, сущности и частицы другого мира | В разработке | В разработке |

## Enhanced Terrain Preview

В расширенном режиме Paper-плагин проверяет ближайший Незер-портал игрока и передаёт ограниченный снимок видимых блоков вокруг его Vanilla-назначения. Клиент получает только компактную палитру материалов и позиции блоков. Каждый блок рисуется как отдельная 3D-геометрия за плоскостью портала; из-за этого ближние и дальние объекты смещаются по-разному при повороте и перемещении игрока.

Снимок включает время мира, дождь и тип измерения. Окно в Верхний мир получает светлое небо и яркую местность днём либо тёмное небо и приглушённые блоки ночью. Для Незера применяется отдельная тёплая палитра тумана. Рендер выполняется с depth-тестом: блоки текущего мира скрывают портал, а фоновая плоскость нового режима перекрывает ванильную фиолетовую текстуру только там, где получены реальные данные от сервера.

## Установка

### Клиент Fabric

1. Установите **Fabric Loader 0.19.3+** для Minecraft **26.2**.
2. Поместите актуальный **Fabric API** и `seamless-portals-*.jar` в папку `mods`.
3. Удалите прежние JAR-файлы Seamless Portals, чтобы не загрузить две версии одновременно.
4. Полностью перезапустите лаунчер и Minecraft.

### Сервер Paper — для живой местности

1. Используйте сервер Paper, совместимый с API 1.21+ и Java 25.
2. Поместите `seamless-portals-paper-*.jar` в серверную папку `plugins`.
3. Перезапустите сервер.
4. Подключитесь клиентом с Fabric-модом. После входа мод выполняет handshake, а затем запрашивает снимок только для близких обнаруженных порталов.

Плагин не принимает от клиента имя мира, произвольную координату назначения или радиус снимка. Сервер сам проверяет исходный портал, выбирает стандартное измерение назначения и ограничивает объём данных.

## Управление

| Клавиша | Действие |
|---|---|
| `F7` | Включить или выключить визуальный эффект Seamless Portals. |
| `F8` | Включить диагностическую информацию о порталах. |

## Сборка

```bash
./gradlew clean build --no-build-cache
```

Готовые файлы появляются в следующих каталогах.

| Артефакт | Путь |
|---|---|
| Fabric-мод | `build/libs/seamless-portals-1.0.0.jar` |
| Paper-плагин | `seamless-portals-paper/build/libs/seamless-portals-paper-1.0.0.jar` |

Каждый push в `main` запускает GitHub Actions, который собирает оба JAR-файла и публикует их как артефакты workflow.

## Ограничения текущей версии

Текущий расширенный режим уже передаёт **реальную форму местности** и рендерит её трёхмерно. Однако в этой версии он использует сетевую палитру материалов, а не полный ванильный atlas/baked-model рендер. Поэтому блоки имеют узнаваемые цвета и освещение, но ещё не обладают пиксельно идентичными ванильными текстурами, сложными моделями, сущностями, частицами, рекурсией порталов или интеграцией с shader packs. Это следующие этапы разработки, а не уже заявленная готовая функция.
